## Behavior Bob should expect

- Ticket rows and ticket-number links go to `/investigations/incident/{incidentId}`. The page calls `GET /api/incidents/{incidentId}/investigation`. A caller that already has the investigation list can go straight to `/investigations/{investigationId}`.
- A saved link that put an incident id under `/investigations/{id}` is recovered. A 404 on that investigation is tried as an incident before the page shows "No such record."
- A valid ticket with no investigation shows the incident summary and Start investigation. Stages `closed` and `approved`, with no investigation, say the ticket is finished and hide the button.
- After start, the page renders the returned investigation and polls `GET /api/investigations/{id}` every 5 seconds.
- `FindActiveByIncidentAsync` is unchanged. It still skips Rejected and Failed. The new lookup is `FindLatestByIncidentAsync`.
- Databases created by `EnsureCreated` already have `Sequence`. On an older `mps.db`, startup adds the column when `pragma_table_info` does not list it, then sets `Sequence` to `rowid`.
