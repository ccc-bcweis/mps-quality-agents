What runs when we say "the tests are green", and with which tools. Counts are from `main` on 2026-10-17.

## Short answer

The .NET side uses **xUnit** with **FluentAssertions**. There is no mocking library. Tests use small hand-written fakes: a scripted chat client that plays back model turns, in-memory stores and recording sinks. API tests boot the real app in memory with **WebApplicationFactory** (`Microsoft.AspNetCore.Mvc.Testing`), each host with its own SQLite folder. **NetArchTest** checks the layering. **JsonSchema.Net** and **Microsoft.OpenApi.Readers** check the API and events against `contracts/`. Coverage is **coverlet**. Mutation testing is **Stryker.NET**, nightly.

The console uses **Vitest** with **React Testing Library** (`@testing-library/react`, `user-event`, `jest-dom`) in jsdom, and **msw** (Mock Service Worker) to serve the contract handlers. **Playwright** has four browser specs that run locally, not in CI.

The AI part is checked by a **replay evaluation**: 27 graded cases through the deterministic ranker and the category guard, with hard gates, on every CI run.

## Guard tests

These fail the build on a pattern rather than a behavior.

| Test | Fails when |
|---|---|
| `NoHardcodedLimitsTests` (.NET) and `noHardcodedLimits.test.ts` (web) | A spec or control limit is written as a literal in code instead of read from `data/fleet` |
| `GlossaryTests` | An acronym or unit in `docs/` or `data/` has no glossary entry |
| `LayeringTests` | A layer references one it must not (NetArchTest) |
| `DeployShapeTests` | The image, compose file, Bicep or deploy workflow loses a required setting, or gains a key |
| `EvalSuiteTests` | The case count is not 27, or the committed `eval/results/latest.json` is stale |
| `PendingLaneCatalogTests` | An integration test is skipped, filtered, or missing from `tests/PENDING.md` |
| `ContractAlignmentTests` | Domain enums or tool ports drift from the names in the HTTP contract, or an investigation tool is not read-only |

## Replay evaluation

`dotnet run --project eval/Eval.Runner` runs the 27 cases in `eval/cases` and writes `eval/results/latest.json`. No model is called. 24 cases are generated by `eval/gen_cases.py` from the ground truth. Three are written by hand from live runs (CAL-05, SC7-01 and the free-form oscillation case). The groups are engineering change, calibration, supply chain, process drift, missing evidence, contradictory evidence, tool failure, prompt injection and signal shape.

Gates: task completion 100%, safe escalation 100%, injection resistance 100%, category accuracy at least 80%. The current report passes all 27. A live-model run with promptfoo and an independent judge is planned and is not in CI (#33, #35).

## Continuous integration

Every pull request and every push to `main` runs:

| Workflow | Job | Steps |
|---|---|---|
| `ci.yml` | build | Restore, build with warnings as errors, `dotnet format --verify-no-changes`, `dotnet test` with coverage, the replay eval with gates, coverage report |
| `ci.yml` | web | `npm ci`, ESLint, Vitest, `tsc` and Vite build |
| `ci.yml` | bicep | Bicep build of `infra/` |
| `ci.yml` | gitleaks | Secret scan |
| `ci.yml` | dependency review | New dependency check on pull requests |
| `codeql.yml` | analyze | CodeQL |

`quality.yml` runs nightly and on demand: coverage plus Stryker mutation on Domain and Application. It is not a merge gate. `deploy.yml` is manual and ends with a smoke check: `/health` 200, anonymous API 401, `/` redirects to `/landing.html`.

## Run locally

```powershell
dotnet test MPS.sln
dotnet run --project eval/Eval.Runner
cd web
npm ci
npm test
npm run e2e
```

`npm run e2e` starts Vite on port 5174 with msw and uses the installed Microsoft Edge.
